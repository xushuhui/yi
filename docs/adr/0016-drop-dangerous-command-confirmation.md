# 不再拦截危险命令

## Status

accepted（取代 ADR-0014）

## 背景

ADR-0014 让 `bash` 在执行 `rm`、`dd`、`sudo` 这类命令前停下来问 `[y/N]`。实际用下来，摩擦大于保护：

- 确认只读**一个字节**，且只认 `y`/`Y`：等待模型时提前敲的字会被它先吃掉，直接判成拒绝；
- 30 秒超时；提示是原地覆盖状态行的一行字，容易被后续输出刷走；
- 管道、脚本、测试里根本没有终端，一律拒绝，模型只能改用别的写法绕；
- 清单本身挡不住 `bash -c 'rm …'`、别名和脚本，是护栏不是沙箱。

同一时期，参考对象 omp 的默认值是 `approvalMode: "yolo"`（全部自动放行），并没有按命令名拦截这一层。用户明确要求去掉。

## 决定

- 删除危险命令清单、执行前确认、`cancel::confirm` 与 `Approval`，`bash` 一律直接执行；
- **不加**配置开关，不留「默认关、可打开」的一层：多一个开关就多一条要维护、要测试、要解释的路径；
- 唯一保留的写保护是计划模式：`write` / `edit` 被拒，`bash` 只放行只读命令。它保护的是「调查阶段别改代码」，不是「删除要确认」。

## 考虑过的选项

- **保留清单，改善手感**（只认 `y`/`n`、其它键忽略、90 秒超时、醒目提示）：解决误判，仍保留一层保护。但用户日常删除频繁，任何确认都是净成本；而且它只挡显式写命令，挡不住同等危险的脚本。否决。
- **配置开关 `approval: auto | ask`**：默认 auto 等于现在的决定，但多一条分支与一份文档。否决，真需要时再加。
- **缩小清单到只剩 `dd`/`mkfs*`/`sudo`**：这些命令日常几乎不用，拦了也几乎不触发，保护价值接近零。否决，不如全删。
- **沙箱/只读账号**：真正的隔离，但引入平台依赖与配置面，超出「单人单机、以 git 兜底」的定位。

## 影响

- 模型执行 `rm`、`dd`、`sudo`、`mkfs` 等不会再问，按 yi 的权限直接跑；
- 误删只能靠 git、备份和事后复核；会话文件里仍完整记录每条 `bash` 命令与退出码；
- 计划模式下的只读白名单不受影响；
- 测试不再需要区分「有没有终端」；管道与测试里删除命令的行为和真终端一致。
