# 表格按显示宽度对齐渲染，超宽先折行

## Status

accepted

## 背景

ADR-0004 决定不重排表格，理由是「中英文混排算宽度容易出错」，只把分隔线调暗。实际使用下来，模型给的表格很常见，原样输出时列宽参差、`|---|` 一行夹在中间，读起来比不渲染还费劲。

约束没变：输出进终端滚动区，不能重绘（ADR-0002），所以必须等整张表到齐才能算列宽。

## 决定

- 表格行先攒着，遇到第一个非表格行（或本轮结束）一次性渲染。
- 列宽按**显示宽度**算：东亚宽字符占两格，ANSI 控制符不计入。
- 样式：**不画竖线**，列之间两个空格，表头下面一条暗色分隔线（`─` 按列宽重复）。对齐标记照做：`:---:` 居中、`---:` 右对齐，其余左对齐。
- 总宽超过终端列数时，先把列宽压进可用宽度（窄列先满足，宽列分摊剩下的空间），再把每格按显示宽度**折行**。行内标记（`**粗体**`、行内代码）整段算一个折行单位，不从中途切开；折行后的每段各自上色。
- 只有连一列都放不下（终端窄到没有可用宽度）时才回退成原样，只把分隔行调暗——信息一个字不丢。
- 终端列数取 `TIOCGWINSZ`；拿不到（管道、伪终端未设宽度）按 80 算。
- 第二行不是分隔行时不算表格，按普通文本处理。

## 考虑过的选项

- **带框线（`┌─┬─┐`）**：好看，但复制时会带上框线字符。ADR-0004 已用同一理由否决过给代码块加边框。
- **超宽时截断列**：能让表格永远放得下，但会丢内容，而模型给的表格常常正是宽的那种。
- **超宽时让终端自己折行**：折行点由终端决定，第二列会掉到第一列下面，列边界全丢。所以折行必须自己做——在每列宽度内折，列边界仍然对得齐。
- **按字符数而非显示宽度对齐**：实现简单，但中文列会整体错位——这正是 ADR-0004 当初回避这件事的原因，现在把它当成必须解决的先决条件。

## 影响

- 表格延迟到整块结束才出现（和代码块一样），流式期间中间几行会先不出来。
- 只有着色模式（终端且未设 `NO_COLOR`）才重排；管道输出保持原样透传，脚本行为不变。
- 列宽按显示宽度估算，emoji 与组合字符按固定规则近似处理，极端混排仍可能差一格。
- 折行后一条逻辑行会变成多条物理行；行数上限按物理行算，长表格会占更多屏幕。
