# 会话分支用追加的 rewind 条目表示

## Status

accepted（取代 ADR-0001 第 3 条里「不做分支、会话树」的部分）

## 背景

用户要 `/tree`：能看到一条会话走过哪些岔路，并回到某条用户消息之前重新开始，旧路径不丢。omp 的做法是给每条记录存 `parentId`、把会话文件本身做成树，切换分支时再用 `branch-summary` 把另一条分支压成摘要。

yi 的会话是一条追加写、不分叉的 JSONL：条目只有单调递增的 `seq`，没有父子指针；上下文 = 最后一条 `compaction` 的 `firstKeptSeq` 之后的全部消息；`AGENTS.md` 里「不做会话树」原本是写死的非目标。

约束：文件是唯一持久状态、可 grep、可审计；前缀不能回改，否则供应商缓存每次失效；行式界面不接管终端按键。

## 决定

- 新增一条记录 `rewind`：`{"type":"rewind","seq","timestamp","toSeq"}`，`toSeq` 是目标分支点（被回退那条用户消息的父条目的 `seq`；`0` 表示回到空会话）。
- 父链规则：普通条目的父是文件里的前一条；`rewind` 条目的父是它的 `toSeq`。从最后一条记录沿父链走到 `0`，得到「当前路径」。
- 上下文、压缩规划、启动重放都只看当前路径；不在路径上的记录保留在文件里，供 `/tree` 展示与切回。
- `/tree` 打印用户消息列表（按 `seq` 升序）：`●` 当前路径、`○` 其它分支、`⑂` 有两条以上子条目的分支点；每条带序号、时间、首行前 60 字。`/tree <序号>` 回退到该条之前，旧路径原样保留，可再切回。
- 回退后把被回退那条用户消息的原文预填进输入行，不自动发送。想改措辞直接改，想原样重来按回车。
- 只允许回退到当前压缩边界之后、且分支点也在边界之后的用户消息；更早的在列表里标「已压缩」或「跨压缩边界」并拒绝。压缩之后的回退不引入分支摘要。
- 不做：`parentId` 字段、单独的分支文件、`/fork`、`/rewind` 别名、Esc-Esc 快捷键、全屏选择器、跨压缩边界的重新摘要。

## 考虑过的选项

- **回退时截断/改写会话文件**：上下文立刻正确，但旧路径不可恢复、审计记录被破坏，也违背「只追加」的缓存与崩溃恢复设计。否决。
- **给每条记录加 `parentId`，把文件做成真正的树**：与 omp 对齐，但现有会话全部要迁移或兼容两套格式；而且「树」的复杂度主要在分支摘要与全屏导航，yi 都用不上。否决。
- **`/tree` 只读，回退另开 `/rewind`**：多一个命令名，行式界面里「看和切」本来就是一件事。否决合并为 `/tree`。
- **跨压缩边界回退并重新摘要**：需要把压缩逻辑改成分支感知，并搬 omp 的 `branch-summary`；压缩在 52 万 token 才触发，日常几乎碰不到，代价与收益不匹配。否决，留作以后。
- **全屏树选择器**：直观，但要引入 `ratatui`/`crossterm` 与按键接管，推翻 ADR-0002。否决。
- **`/fork` 另起会话文件**：是会话管理而不是分支浏览，第一期不做。

## 影响

- 会话文件只增不减；一次回退多一行，切换回来再多一行。
- 回退不会撤销已经发生的文件改动与工具副作用；它只改变模型看到的上下文。`/tree` 的提示里写明这一点。
- 压缩只摘要当前路径；被抛弃分支上的记录进入摘要是不可能的（它们在路径之外），但会永远留在文件里。
- 老会话文件没有 `rewind` 条目，父链退化成文件顺序，行为和以前逐字节一致。
- 一个已知的边界：`/tree` 选中「第一条可见消息」时，它的父条目可能落在压缩边界之前，此时拒绝回退；压缩边界上那条消息因既有实现（`seq > boundary`）本就不在上下文里。
