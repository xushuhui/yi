# 后台命令的结果以「用户消息」回灌，不用新角色

## Status

accepted

## 背景

`bash` 带 `background: true` 时命令丢到后台，这一轮不等它。问题是结果跑完之后怎么让它重新进入对话：

供应商接口里，工具结果必须紧跟在发起它的那次工具调用之后。后台命令的调用早已用「已转入后台」这句工具结果回答过了，再补一条同一 id 的工具结果会被拒；而 yi 现在只有三种消息角色：用户、助手、工具。

## 决定

后台命令完成时，**在下一轮对话开始处追加一条用户消息**：

```
[后台作业 bash-1 完成，用时 12.3s，命令：go test ./...]
<命令输出>
```

- 只在你下一次提交时回灌，不打断正在进行的输出，也不主动弹提示；界面上同时打一行「· 后台作业 bash-1 完成（12.3s）：go test ./...」。
- 同时最多 3 条后台命令；退出 yi 时整组杀掉还在跑的进程。
- 后台命令不响应这一轮的 Ctrl-C：它被明确放走了，不该被连坐。

## 考虑过的选项

- **补一条工具结果**：协议不允许——每次工具调用只能被回答一次，重复 id 会被供应商拒绝。
- **加一个「系统」角色**：OpenAI 兼容接口支持 system 消息，但它在对话开头，插到中间会破坏前缀缓存，还要改会话格式与渲染。
- **不动会话，只打印到屏幕**：模型看不到结果，下一轮还得自己再跑一遍，等于白跑。
- **完成即打断当前一轮注入**：行式界面里插入时机难做对（模型可能正在输出），要先做队列和中断；收益不抵复杂度。

## 影响

- 会话文件里会出现 `role: user`、内容以 `[后台作业 …]` 开头的条目。人和模型都能看懂，但严格说它不是用户打的字——`prompt` 条目（上键历史）不会记录它，两者是分开的。
- 前缀缓存：回灌发生在用户提交前，追加在尾部，之前的缓存前缀不受影响。
- 渲染：启动重放时跳过这类条目——它不是人打的字，而且可能一次带几十 KB 输出。
