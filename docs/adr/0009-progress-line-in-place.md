# 处理中状态只重画一行，其余仍是行式输出

## Status

accepted

## 背景

一轮对话里有三段是完全没有输出的：等模型第一个字节（可能几秒）、模型输出思考内容（默认隐藏）、工具执行（`bash` 可能跑几十秒）。屏幕上什么都不动，分不清是「在干活」还是「卡死了」。

ADR-0002 定下的是行式输出：只往下打印，一轮结束打一行页脚，不引入全屏布局。现在要补一个「还活着」的信号，问题是它能动多少。

## 决定

在输入行的位置维护**一行**处理中状态，用回车符回到行首、清掉整行再重写：`等待模型 3.2s`、`思考中 1.1s`、`运行 bash 12.4s`。

- 只在标准输出是终端时显示；管道、重定向里一个字节都不写。
- 每 200 毫秒最多重画一次。
- 有正文、工具调用、工具结果或提示要打印时，先擦掉这一行再打印，状态行不留在历史里。
- 阶段由已有事件驱动（开始一次请求、收到思考内容、开始执行某个工具），不加新的阶段协议。
- 心跳不发新线程：请求等待循环本来就每 100 毫秒转一次，`bash` 等待进程也每 50 毫秒转一次，顺手发一个 `Tick`。

这只是 ADR-0002 的一个窄例外：**允许改写当前这一行，仍然禁止全屏重绘**。

## 考虑过的选项

- **全屏 + 常驻状态栏**：状态永远可见、不占输出行。代价是要重做滚动、翻页、缩放、复制，等于推翻 ADR-0002。
- **每进入一个阶段打印一行静态提示**：实现最简单，但一轮里会堆三四行「等待模型…」，翻历史时全是噪音。
- **转圈动画加秒表**：看着最「活」，但每 100 毫秒重画、还要和流式正文抢同一行，容易花屏，收益不抵风险。
- **单行原地刷新 + 阶段名与耗时**（采纳）：一行、几行代码、不花屏，信息量正好够判断「是不是卡了」。

## 影响

- 界面层多了一个「改写当前行」的能力，只在 `src/main.rs` 里；核心库照旧只往回调外发事件。
- 状态行依赖 `Event::Tick` 心跳；心跳离开终端也无害，只是没有界面去画。
- 用管道或重定向跑脚本时，输出与以前逐字节一致。
