# Esc 也取消本轮

## Status

accepted（在 ADR-0005「一轮之内按键归取消模块」的基础上扩展，键盘归属不变）

## 背景

取消本轮原来只认 Ctrl-C。Ctrl-C 在某些终端里被配置成复制、或在 tmux 里被改键，用户按 Esc 想中止当前回答时没有反应；omp 与多数终端 agent 都用 Esc 中止。

难点在于 Esc 同时是控制序列的前缀：方向键是 `ESC [ A`，应用光标模式是 `ESC O A`。如果见到 `ESC` 就取消，方向键一按就会误伤。

## 决定

- `cancel::poll_terminal` 读到 `0x1b` 时先挂起，最多等 20 毫秒看后续字节：
  - 有后续字节：把 `ESC` 和它一起交给 `Draft` 判断，`ESC [`、`ESC O` 按控制序列整段吞掉，不取消；
  - 没有后续字节：确认是单独一个 Esc，置取消标志，与 Ctrl-C 同一条路径。
- `Draft` 把 `ESC O` 也识别为控制序列开头（原来只认 `ESC [`），否则 SS3 方向键的结尾字母会漏进轮内草稿。
- 输入行（提示符处）的 Esc 行为不动，仍归 reedline。
- 取消后的行为与 Ctrl-C 完全一致：会话保留、草稿预填回提示符、`program_status` 回到闲置。

## 考虑过的选项

- **见到 `ESC` 立刻取消**：方向键、Alt-组合键都会误触，不可用。否决。
- **只在 `ESC` 后跟 `[`/`O` 时取消、其它一律不取消**：反了；单独 Esc 才是「取消」，序列才是「按键」。否决。
- **等待更久（100 毫秒）**：切分到达的序列更稳，但取消手感变钝；终端通常一次 `write` 送完整序列，20 毫秒在实测里足够。否决。
- **改由行编辑器在轮内处理 Esc**：轮内没有行编辑器（键盘归取消模块），要恢复接管就得两套按键状态机，正是 ADR-0005 之前反复出问题的地方。否决。

## 影响

- 轮内单独按 Esc 会中止当前这一轮；`ESC [` / `ESC O` 序列不受影响。
- 极端情况下终端把序列拆开且间隔超过 20 毫秒，可能被当成 Esc 取消一次；继续按一次回车就能接着用，不接受这个代价的反面（迟滞的取消）更糟。
- 只影响一轮进行中的键盘处理；管道与重定向没有变化。
