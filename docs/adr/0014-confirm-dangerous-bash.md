# 危险 bash 命令要人当场确认

## Status

superseded by ADR-0016

## 背景

`bash` 工具默认直接执行命令。`rm`、`dd`、`mkfs`、`git reset --hard` 这类命令一旦跑错，损失不可逆；而模型看不到「这个目录是刚写好的」「那条分支还没推」。用户要求：危险的命令必须由人点头才能执行。

当时的约束：单进程、行式界面、没有审批沙箱；一轮之内终端处于原始模式，`cancel.rs` 已经在逐字节读键盘（Ctrl-C 置取消标志，其余进草稿）。

## 决定

- 在 `bash` 执行前做一次模式匹配；命中危险清单就停下来问：`允许执行危险命令？<命令> [y/N]`。
- 只认 `y` / `Y`；其它键、Ctrl-C、30 秒无回答，都按拒绝处理，命令不执行，回给模型一条 `ERROR:`。
- 标准输入不是终端时（管道、CI、测试）一律拒绝，提示「需要可交互终端」。没有 `/allow`、没有跳过开关。
- 清单固定：`rm`、`dd`、`truncate`、`shred`、`sudo`、`kill`/`pkill`/`killall`、`mkfs*`、`mke2fs`、`newfs_*`、`diskutil` 的 `eraseDisk`/`eraseVolume`/`reformat`/`partitionDisk`/`zeroDisk`；`find -delete`/`-exec`、`xargs rm`。`git` 不在清单里，仍按全局规则「当前消息明确授权」处理。重定向 `>` 也不在清单里。
- 匹配沿用只读检查的分词方式：按 `&&`、`;`、`|`、换行分段，每段看第一个词（`/bin/rm` 取 basename）。

## 考虑过的选项

- **预批准清单 `/allow rm`**：不用打断执行，但批准的是「整个类别」而不是眼前这条命令，风险更大；也解决不了「想看一眼再决定」。否决。
- **开关 `--yes-dangerous`**：管道场景方便，但等于多一条静默删文件的路径，与「必须我允许」相反。否决。
- **把 `git commit` 也纳入**：本地提交可改可撤，每次都拦会烦；全局 Git 规则已经约束。否决。
- **把 `rmdir`/`mv`/关机命令算作危险**：`rmdir` 只删空目录；`mv` 是移动/改名；`shutdown`/`reboot`/`halt`/`poweroff` 影响整机、不在仓库范围内——用户判断这些不需要逐条确认。否决，已从清单移除。
- **把 `chown` 算作危险**：和 `chmod` 一样属于权限调整，不属于删除类；用户判断不需要确认。否决，已从清单移除。
- **把 `chmod` 算作危险**：权限调整不属于删除类，临时改权限也会被拦；用户判断不需要确认。否决，已从清单移除。
- **把 `sed -i` 算作危险**：临时改文件验证「测试能变红」时被拦，只能改用 `edit`。`sed -i` 是文件编辑、git 可恢复，闸门留给删除与提权。否决，已从清单移除。
- **把重定向 `>` 算作危险**：`>` 确实能覆盖文件，但它也是 `2>/dev/null`、写临时文件这类常规写法，拦起来频繁误报。用户判断重定向不属于危险命令；覆盖风险由 git diff 与事后复核承担。否决。
- **系统级沙箱**：真正能锁死，但引入平台依赖与配置面，超出这一期。

## 影响

- 危险命令多一次按键；正常轮次不会被拦。
- 模式匹配挡不住 `bash -c 'rm …'`、别名、脚本文件；这是护栏，不是沙箱。真要隔离得靠只读账号或容器。
- 管道与测试里不能跑危险命令；需要时改用临时目录里的普通命令。
- `cancel::confirm` 复用轮内的原始终端与轮询逻辑；状态行在提问前被擦掉，回答后重新绘制。
