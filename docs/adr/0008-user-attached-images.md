# 用户贴图：认路径，不抢热键

## Status

accepted

## 背景

模型已经能通过 `read` 工具看图，但用户没有入口：想让它看一张截图，只能先让模型自己去读文件路径。omp 的做法更直接——Ctrl+V 贴剪贴板截图、拖拽图片、粘贴路径、或写 `@路径`。

yi 是行式界面，按键由行编辑器接手；Ctrl+V 在它那里已有含义。要改成 omp 那样，得打开行编辑器的自定义按键绑定（ADR-0003 当初刻意关掉的一组），并接管一个已被占用的键。

## 决定

- 只做**路径识别**：整行就是一个图片路径，或正文里写 `@路径`。拖拽图片到终端本来就会产生路径文本，所以拖拽也顺带支持。
- 路径相对项目根解析；必须是存在的文件，且扩展名是 png/jpg/jpeg/gif/webp。不满足就当普通文字，不报错。
- 命中后，这张图作为一条图片消息跟着这句话一起发出去，终端先打一行「图片：<路径>」让人看见自己贴了什么。
- 不缩放：超过 20 MB 明确拒绝，不猜、不静默。
- 不读剪贴板，不做 Ctrl+V，不加 `image` 依赖。

## 考虑过的选项

- **Ctrl+V 读剪贴板截图**：最接近 omp 的体验，但要开行编辑器的自定义绑定、抢一个已有含义的键，且每次取图要起一个 `osascript` 进程。收益集中在「截图」这一种来源上，先不做。
- **`/img` 斜杠命令**：不用抢键，但比直接贴路径多一步，且路径识别已经覆盖了拖拽与复制路径两种来源。
- **引入 `image` crate 自动缩放**：omp 有自动缩放是因为它有图像库；这里一张截图通常几百 KB，为极端情况引入一组依赖不划算。真撞上 20 MB 的图再重新权衡。

## 影响

- 只有「用户贴的图」变了；模型用 `read` 看图的路径完全不动。
- 图片在会话文件里只存路径，请求时才读盘编码；路径失效时请求里会出现「图片 路径 读不到了」的占位说明，不致于让整轮失败。
- 剪贴板图片仍属范围外，等真的觉得「先存成文件再贴路径」麻烦时再说。
