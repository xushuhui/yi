# 消息区块用底色区分

## Status

accepted

## 背景

行式界面里，用户输入和模型回复都打在同一个默认底色上，长对话滚动起来分不清哪句是谁说的。omp 的做法是给每条消息铺底色：用户消息 `#1F2029`（`userMessageBg`），页面与回复 `#282A36`（页面背景），文字左右各留一格、上下各留一行。用户要求 yi 也做成这样（截图取自 omp 的 `dark-dracula` 主题，实测像素值即上述两色）。

`render` 之前只决定前景色；输出走 `print!` 流式打印，终端背景色只对真正写出的格子生效，句子打完就停在半行，色带会断在句尾。

## 决定

- `Theme` 增加两个底色字段：`user_bg`（`#1F2029`）与 `page_bg`（`#282A36`）。
- 输入行重绘：提交后按“提示符 + 原文”的显示宽度算出 reedline 折了几行，光标上移清行，再铺“上留白 + 文字 + 下留白”三到多行，左右各留一格；显示宽度按东亚宽字符两列算。
- 回复区用 `Band` 输出层：每次 `paint` 记住当前列，遇到换行先补满整行（包括最后一列）再复位，行内出现 `RESET` 后立刻补回底色；`close` 处理收尾的半个行。页脚一并算进回复区，状态行借用同一底色。
- 表格按终端宽度减 2 排版，给左右留白让位。
- 重启后的重放同样铺底色：用户块用 `user_bg`，回答用 `page_bg`。
- 只在标准输出是终端且未设置 `NO_COLOR` 时启用；管道与重定向一个字节都不变。

## 考虑过的选项

- **只给输入行铺底色，回复区留给终端默认背景**：省掉 `Band`，但两块的观感取决于用户终端主题，换台机器就不再是 omp 的效果。否决。
- **靠 `ESC[K` 擦除行并依赖终端的“擦除用当前背景色”（BCE）**：少写空格，但 BCE 不是所有终端都支持，背景会时有时无。否决，改成自己补空格。
- **卡片：再给左右各加一列实心边、上下各加一行内边距、画圆角**：更像面板，但每行可用宽度再少两列，窄终端折行更严重；行式界面也没有可靠方式画圆角。暂缓。
- **整个页面（含启动横幅、斜杠命令输出）统一铺页面底色**：与“只追加、交给终端滚动”的行式原则冲突，且斜杠命令输出需要单独重排；现在只覆盖对话本身。否决。

## 影响

- 每个正文行少两列可用宽度，表格按 `width - 2` 收缩。
- 输入块重绘依赖行数估算：估多会擦到上面一行，估少会把文字挤进下留白。已在伪终端里覆盖 20/30/40 列、纯 ASCII 长句、中文宽字符、恰好撑满一行等边界；若以后换掉 reedline 或其绘制方式，需要重测。若估算不可靠，升级路径是提交前用 DSR（`ESC[6n`）问一次光标行列，按实际行数重绘。
- 页脚不再是“完全无色”：前景仍无色，但落在页面底色上；这与 omp 一致。
- 颜色与间距集中在 `Theme` 与 `Band`/`user_block` 两处，改底色只动常量。
