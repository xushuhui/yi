# 界面先行式输出，全屏推迟到真痛了再说

## Status

accepted

## 背景

要常驻一行状态栏（模型、上下文占用、缓存命中、推理强度），就必须全屏重绘：输出区、输入框、状态栏三块布局，并且要自己实现滚动、翻页、窗口缩放、选中复制。这些在行式模式下全部是终端原生能力，一行代码都不用写。代价只是：状态栏那一行变成每轮结束后打印的一行页脚。

## 决定

第一期用**行式输出**：流式打印正文，一轮结束打印一行页脚，然后等标准输入的一行。不引入 `ratatui` 和 `crossterm`。

## 考虑过的选项

- **全屏 + 常驻状态栏**：第一天就像 omp。代价是里程碑 ① 从半天变成几天，且要重做终端已经免费提供的滚动与复制。
- **行式输出 + 每轮页脚**（采纳）：数字一个不少，界面代码接近零，依赖从约 80 个包降到约 33 个。

## 影响

- 模型输出期间不能打字、没有常驻状态栏、没有应用内滚动——这些都依赖终端自身能力。
- 因为 agent 核心与界面之间只有 `submit` 一个接缝，将来换全屏只动展示层，不动核心。
