# 行式界面里渲染 markdown，代码块交给 bat 着色

## Status

accepted

## 背景

模型默认用 markdown 回答：标题、列表、行内代码、代码围栏、表格。原样打印时这些标记全变成噪声（`**粗体**` 带着星号、代码没有颜色），和 omp 的观感差距主要在这里。

约束来自 ADR-0002：输出直接进终端滚动区，不能重绘、不能上移光标。omp 是全屏 TUI，可以先打印再擦掉重画；我们不行，所以「代码先原样输出、块结束后再重画成彩色」这条路不成立，只能先缓冲再一次性输出。

## 决定

- 自己实现行式 markdown 渲染（`src/render.rs`）：按行处理，收齐一行才输出，保证样式不会跨行断裂。
- 代码块（``` 或 ~~~ 围栏）先攒在内存里，遇到结束围栏后整块交给 `bat` 着色，用 `--style=plain --paging=never --theme=ansi`：ansi 主题跟随终端配色，和用户自己的主题一致。
- 行内样式（反色行内代码、粗体、斜体、链接、列表圆点、引用竖线、表格分隔线调暗）在行内处理；表格不重新对齐，中英文混排算宽度容易出错，保留原样只调暗竖线。
- 只在标准输出是终端且没有设置 `NO_COLOR` 时着色；其余情况整个渲染器原样透传，管道输出与脚本行为不变。
- 工具结果只在两种情况下显示：失败时打一行红色原因，`edit` 成功时打一行绿色摘要。完整输出不回显——模型已经看过，回显会淹没正文。
- 除了 markdown 解析器和 bat 调用，不引入新依赖：bat 是可选的外部命令，没装就退化成无色代码块。

## 考虑过的选项

- **引入 `syntect`**：效果好、无外部进程，但直接依赖会正好用满第 6 个名额，依赖树从 78 个包涨到约 120 个，二进制明显变大。否决。
- **自己按关键字着色**：零依赖，但只能认出注释、字符串和关键字，遇到 diff、json、yaml 就露怯。否决。
- **逐行流式着色**：代码块不必等待，但多行语法（块注释、字符串续行）会错色，而且行式界面无法回改。否决。
- **把代码块逐行加边框前缀**：好看，但用户复制代码时会带上边框字符。否决。

## 影响

- 代码块会晚一点出现：模型写完这个围栏才显示。普通正文仍是逐行实时打印。
- 每个代码块一次 `bat` 进程调用，约 10–30 毫秒；块特别大时会有一点停顿。
- `NO_COLOR`、重定向输出、管道测试都走原样透传，不会被样式污染。
- 渲染只发生在界面层，`Event::Text` 和会话文件里仍然是模型原始输出。
