# 接管终端按键，换来上键历史

## Status

accepted

## 背景

行式界面下，按键先由终端的行缓冲处理：它负责回显、退格，直到回车才把一整行交给程序。方向键在这一层没有含义，只会作为 `^[[A` 之类的字符混进输入，程序看不到「用户按了上键」这件事。

要让上键召回之前输入的话，就必须把终端切到原始模式，逐字节读按键，并自己负责回显、光标和删除。这不是加一个功能，而是把一件终端原本免费提供的职责接过来。

同时，历史不能直接取自会话文件里的用户消息：`/skill:go-rules` 这类输入在提交前会被展开成一整篇技能正文，会话文件里存的是展开后的文本，按上键召回会得到一大段文档，而不是用户敲的那句话。

## 决定

- 用 `rustyline` 做行编辑，只用它核心的能力（上下键历史、左右移动、退格、Ctrl-A/E）。关闭默认特性 `with-file-history`、`with-dirs`、`custom-bindings`：历史存在会话文件里，不需要它自己的历史文件和目录解析。
- 只在标准输入是终端时接管按键；`echo ... | yi` 这类管道输入继续走逐行读取，脚本与冒烟测试不受影响。
- 用户原文以 `prompt` 条目写进会话 JSONL，不进入模型上下文，压缩也不带走。上键历史取最近 200 条，连续重复只留一条。
- Ctrl-C 放弃当前输入行并回到提示符；Ctrl-D 退出。模型输出期间按 Ctrl-C 仍然直接结束进程，那属于另一件事，本期不改。
- 不做 vim 键位模式，也不加 `edit_mode` 配置：现在只服务一种键位，多一个配置项就多一条没人验证的分支。

## 考虑过的选项

- **手写最小行编辑器**（`libc` 切原始模式，约 150–250 行）：不新增包，但终端恢复、中文宽度、粘贴、Ctrl-C 全要自己扛，一处没兜住就会把用户的终端留在原始模式。否决。
- **不做方向键，改用 `/history` 命令列出编号**：零终端控制，但不是「按上键」的直觉，多一步操作。否决。
- **`rustyline` 默认特性**：会多带文件历史、目录解析、自定义键位绑定几组包，而这些都用不到。改为 `default-features = false`。
- **同时做 vim 键位**：需要重建「模式 + 动作 + 操作符」的状态机，且 Esc 与中文输入法的交互要真机验证才知道顺不顺手。推迟到有实际需求时再说。

## 影响

- 直接依赖 3 → 4 个（上限 6），整个依赖树 64 → 78 个包，二进制增大（rustyline 及其依赖）。
- 输入路径分成两条：终端走行编辑，非终端保持原来的 `read_line`。两条都必须保留，否则管道用法和现有测试会坏。
- 历史随会话走：`/new` 归档后，新会话的历史从空开始；旧提示词仍在归档文件里，可以直接 grep。
- `Ctrl-C` 在输入行里不再等于退出，退出统一用 Ctrl-D。这是与之前行为唯一的可见变化。
