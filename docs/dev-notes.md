# yi 开发笔记：设计思路与踩过的坑

这份文档写给两类人：半年后的我自己，和第一次读到这个仓库的人。它不讲接口细节（那些在 `spec.md` 和 ADR 里），只讲两件事——**当初为什么这么设计**，以及**开发中被什么坑绊倒、怎么爬出来的**。

---

## 一、最开始的想法

### 起因

我用 omp 做日常开发，三个地方拖慢我：

- **内存**：机器上同时跑着 15 个 omp 进程，合计约 1.5 GB；单个界面进程最高 358 MB；安装包 199 MB；数据目录 531 MB。
- **功能**：它的能力我大部分没用过。统计下来，真正每天用的只有五个动作——读文件、改文件、执行命令、搜索、写文件，占全部 39,886 次工具调用的 90.7%。
- **会话模型**：它要求「结束一个会话再开一个」。我在多个项目间来回切换，39 个项目攒出 181 条会话，上下文不断断裂。

所以目标很朴素：**一个常驻终端的小程序，一个项目一条对话，只做我每天真的会用的动作。**

### 五个定调的决定

1. **单进程、单供应商、单模型**。
   不做多 agent、不做多供应商切换。一个二进制，一份配置，出问题时只有一条链路要查。

2. **行式界面，不做全屏**。
   全屏意味着自己重做滚动、翻页、选中复制、窗口缩放——这些终端本来就免费给。代价只是把常驻状态栏变成每轮结束打一行。这条写成了 ADR-0002。

3. **一个项目一条会话，一个会话一个文件**。
   项目按「启动时所在目录的绝对路径」精确匹配；在子目录启动算另一个项目。不需要「结束会话」，想换话题用 `/new`，旧文件改名归档，还能直接 grep。

4. **改文件靠锚点，不靠行号猜**。
   读文件时返回首行 `[路径#TAG]`，`TAG` 由文件内容算出。改文件必须带同一个锚点，且只能改这次真正看过的行；文件被别人改过，锚点对不上就拒绝。这样模型不会在过期的行号上瞎改。

5. **上下文自动压缩，不让人管**。
   输入超过模型窗口的 50%（`deepseek-flash` 是 1,048,576，所以是 524,288）时，本轮结束后把最早的一段对话压成摘要，保留最近约 20,000 token 的原文。用户不用记着自己清上下文。

另外两条「不做」：不做记忆与自学习，不做会改变行为的隐藏自动化。出了问题要能一眼看出是谁干的。

## 二、踩过的坑

下面按「现象 → 原因 → 怎么修」记录。每一条都来自真实使用，不是假设。

### 1. 状态栏显示「上下文 97%」，看着像快满了

**现象**：一轮里调用了几十次工具，页脚百分比飙到 97%，但会话并不长。

**原因**：百分比用的是「整轮所有请求的输入 token 累加」。工具调用越多，这个数越大，和「上下文此刻多大」没有关系。

**修法**：单独记录最后一次请求的输入量，占窗口比例才是真实上下文。累加值继续用于成本统计，但不再冒充上下文。

**学到**：一个指标要么是「当前状态」，要么是「累计消耗」，不能混在同一个数字里。

### 2. 删一个接口，跑到一半被强行掐断

**现象**：在真实项目里删一个 HTTP 接口，模型改了 handler、业务层、测试、文档，第 41 次模型请求后突然停下，话说到一半。

**原因**：我当初拍脑袋定了一个「一轮最多 40 次请求」的上限，没有任何依据。那次任务正好用满 41 次。更糟的是，超限只打印一行错误到屏幕，会话文件里什么都没留。

**修法**：查了 omp 和 pi 的做法——两边都没有总步数上限，防的是「同一个失败调用反复重试」。于是删掉总上限，改成：同一个调用（工具名和参数完全相同）**连续失败 3 次**才停，停下前先让模型说明现状，不把话停在半句。

**学到**：用「有没有进展」判断该不该停，比用「总共跑了多少步」更接近事情的本质。真实任务里步数多不等于出问题。

### 3. 失败了，但事后翻遍文件找不到原因

**现象**：网络错误、超限、压缩失败都只在屏幕上闪一下，滚动过去就没了。

**原因**：会话文件只存对话（用户、助手、工具结果），运行时错误没地方落。

**修法**：会话文件新增 `notice` 条目，失败原因、超限、取消都写进去；它不参与模型上下文，压缩也不会带走。事后 `grep '"type":"notice"'` 就能看到。

### 4. 按 Ctrl-C，整个进程没了

**现象**：模型跑偏时想中断，Ctrl-C 直接把 yi 杀了，这一轮不但没停好，还没落盘。

**原因**：没有信号处理，默认行为就是终止进程。

**修法**：一轮请求期间接管 SIGINT，只置一个「取消」标志；请求和读响应都放在工作线程里，主线程每 100 毫秒检查一次标志，所以模型还在「思考」、一个字节都没吐时也能立刻停。命令执行期间同样检查，命中就杀掉进程组。

后来发现还有一层：行编辑器会把终端留在 raw 模式，ISIG 关着，这时 Ctrl-C 根本不产生信号，只是一个字节 0x03。所以检查函数还兼做一件事——用 `poll` 看一眼终端，读到 0x03 也当成取消。两条路（信号、字节）落到同一个标志。代价是流式输出期间手打的字符会被丢弃，反正那一轮结束前也没人会读它们。

### 5. 一条后台命令把 yi 卡死二十分钟

**现象**：执行 `python3 srv.py & sleep 1` 之后，yi 再也没有返回，进程活着但没有子进程。

**原因**：后台进程继承了命令的 stdout/stderr 管道。shell 自己退出了，但后台进程还活着，管道永远不会 EOF；bash 工具在 `join` 读线程时无限等待。超时机制也管不到，因为它检查的是「等 shell 退出」那一步。

**修法**：读线程改成往共享缓冲写，主流程在 shell 退出后最多再等 300 毫秒取快照，然后返回。后台进程继续跑，但不再拖住 yi。

**学到**：`join` 一个可能永远不结束的线程，等于把整个程序押在别人身上。任何「等别人结束」的地方都要有上限。

### 6. 中断之后再说话，被供应商 400 拒绝

**现象**：报错 `An assistant message with 'tool_calls' must be followed by tool messages responding to each 'tool_call_id'`。

**原因**：中断或崩溃发生在「助手消息已经写盘、工具结果还没写完」的中间。供应商要求两者严格一对一，缺一条就整轮拒绝。

**修法**三层：
1. 取消时，把这一批里没执行的调用各补一条「没有执行」的结果；
2. 启动时，如果尾巴上还缺，直接补一条「上一轮被中断」；
3. 构造上下文时兜底：中途断开、没法靠追加修好的回合，整条丢掉（连同它那几条孤立的工具结果）。

**学到**：任何「两次写入才算完整」的数据，都要考虑只写了第一次就断电的情况，并在读取时能自愈。

### 7. 崩溃了什么都没留下

**现象**：进程 panic 后会直接退出，会话文件停在一个工具结果上，事后完全不知道哪里崩了。

**修法**：启动时装一个 panic 钩子，把崩溃原因和代码位置（`文件:行:列`）写成一条 `notice` 再退出。

### 8. 一条含中文的命令直接把进程干崩

**现象**：`panicked at src/tools.rs:197: assertion failed: self.is_char_boundary(new_len)`。

**原因**：为了让终端回显短一点，代码对命令用了 `String::truncate(80)`——它按**字节**截断。第 80 个字节正好落在汉字「中」的中间，Rust 直接 panic。

**修法**：命令行不再截断，整条显示；错误信息里那处截断改成先退到字符边界。两条回归用例锁住。

**学到**：中文环境里，任何按字节切字符串的地方都是雷。要么按字符切，要么先确认边界。

### 9. 中文路径下，语言服务拿不到定义

**现象**：文件在「中文 目录」里时，跳定义返回空片段，诊断永远是「没有诊断」。

**原因**：传给语言服务的文件 URI 只把空格转成了 `%20`，中文原样塞进去。服务器回传的是完整百分号编码的 URI，两边对不上。

**修法**：写一个完整的百分号编解码（保留字母、数字和 `-._~/`，其余按 UTF-8 字节编码），列号按 UTF-16 计算。真实中文路径的用例验证通过。

### 10. 语言服务的「空闲十分钟回收」其实是句空话

**现象**：规格写着空闲十分钟自动终止，代码却只在「下一次调用」时顺带清理。

**修法**：起一个后台线程，每 60 秒扫一次，超过十分钟没用的进程杀掉；`yi` 退出时全部终止；服务器自己崩了，下次调用自动重起。

**状态**：回收逻辑上了，但没有自动化用例（要等十分钟或注入测试参数，不值）。

### 11. 让模型别写 `cd`，它不听

**现象**：工具说明写明「工作目录已是项目根，别写 `cd`」，模型在旧会话里依然每次都写 `cd /Users/xsh/… && …`。

**原因**：这条会话的历史里已经有几十条 `cd` 的例子。上下文里的示范，压过了工具说明。

**修法**：显示层和执行层都做确定性归一化——命令开头若是 `cd <项目根> && `，直接剥掉再执行（语义完全等价）。指向别的目录的 `cd` 原样保留。

**学到**：能靠代码保证的事，别指望提示词。提示词对「干净历史」有效，对「已经跑偏的历史」基本无效。

### 12. 上键翻不出历史

**现象**：升级后第一次按上键，什么也没有。

**原因**：历史只记录「用户敲进终端的原文」，而这条功能上线前的会话里一条记录都没有。另外 `/skill:` 会把整篇技能正文展开后写进会话，如果直接拿会话消息当历史，召回的就是一篇文档。

**修法**：新增 `prompt` 条目专门存原文；老会话没有它时，退回用用户消息回填，并跳过以 `[技能 ` 开头的展开内容。

### 13. `/skill: doc` 找不到技能

**现象**：冒号后面加个空格，补全和技能调用都没反应。

**原因**：补全看到「第一个词里有空格」，以为用户已经在写要求，直接放弃；技能展开那边则把名字解析成空串。

**修法**：两处都允许冒号后任意个空格。

### 14. 模糊匹配明明有结果，按 Tab 只听到一声「叮」

**现象**：输入 `/skill:rev`，候选里确实有 `code-review`，但第一次 Tab 不补全。

**原因**：行编辑库在「候选没法延长公共前缀」时会先响铃，等第二次 Tab 才列菜单。对前缀匹配不痛不痒，对子序列匹配就很别扭。

**修法**：如果没有候选以已输入内容开头，只返回最匹配的一条，Tab 直接替换。

### 15. 行内代码看起来「没有颜色」

**现象**：用户说整屏没颜色。截图上标题加粗了，但没有任何色相。

**原因**：行内代码用的是「反色」（`\x1b[7m`），在深色终端里就是一块白底，看起来像没上色；而那段回答没有 `#` 标题、也没有代码块，唯一被上色的只剩那一块白。

**修法**：行内代码改成黄色前景，列表序号上色，工具行箭头青色。想确认终端本身支持 ANSI，可以直接 `printf '\e[33m黄\e[0m\n'`。

### 16. 代码块下面多一个空行

**原因**：代码行被缓冲时不输出，但外层仍然给它补了一个换行。

**修法**：被缓冲的行返回「不要输出」，由外层决定换行。

### 17. heredoc 里的代码全是白字

**现象**：`cat > srv.py <<'EOF' … EOF` 这段，正文没有语法高亮；omp 会把 heredoc 当 Python 上色。

**修法**：识别 heredoc 的结束标记，语言按「解释器 → 目标文件后缀 → 结束标记」推断，整段交给 `bat` 着色；认不出来或没装 bat 就原样输出，一个字都不丢。

### 18. 失败时那行红字显示的是输出的第一行

**现象**：命令以非零码退出，界面显示 `✗ bash import sys`——「import sys」只是脚本的第一行，不是失败原因。

**修法**：优先找结尾的「退出码：N」行，找不到才退回第一行。

### 19. 同一件事有两种配法

**现象**：语言服务器的启动命令既写死在代码里，又能被配置文件覆盖，而帮助文字里只字未提。

**修法**：固定取 PATH 里的 `gopls` / `phpantom_lsp`，配置文件里写了也忽略。

### 20. 说好只接一个供应商，后来接了第二个

**现象**：日常主力从 DeepSeek 官方的 `deepseek-flash` 换到了 OpenCode Go 的 `deepseek-v4.1-flash`——另一个地址、另一把密钥、另一个窗口大小。

**原因**：ADR-0001 当初判断「抽象的收益来自第二个供应商，而第二个供应商不会出现」。这个判断错了：出现的是两个具体地址，不是一场需要抽象的多供应商。

**修法**：不写适配层，写一张两行的预置表，每行带地址、默认模型、窗口、密钥环境变量名；配置只写 `provider` 选哪一行。窗口不再是一个全局常量，页脚百分比和压缩阈值都跟着预置走。密钥只读环境变量——配置文件会被同步、备份、误提交。

**学到**：判断「某种情况不会出现」时，要问它消失的原因是什么。这次的答案是「没有原因，只是当时没得选」。

### 21. 页脚从一项信息变成五项，没有变全屏

**背景**：omp 的状态栏常驻底部，路径、分支、上下文、三个订阅限额、供应商、模型挤在一行。想要一样的效果，就得做全屏（ADR-0002 否决过）。

**修法**：只把「本来就知道的信息」加进每轮那一行：项目路径（家目录缩写 `~`）、当前分支、上下文占比、供应商、模型。配额是订阅信息，需要额外联网，不进页脚。分支每轮跑一次 `git rev-parse --abbrev-ref HEAD`，一轮多一次进程启动，相对模型延迟可忽略。

**学到**：常驻状态栏的价值在「随时可见」，行式界面的价值在「滚动、复制、搜索全免费」。先问「这条信息我要不要随时看见」，再决定要不要为此推翻界面形态。

### 22. 换到 opencode-go 之后，第一句话就被 400 挡住

**现象**：接上 OpenCode Go，发第一句就报 `HTTP 400 {"type":"error","error":{"type":"MissingSessionID",...}}`，提示缺 `x-opencode-session`。

**原因**：opencode-go 不是普通的 OpenAI 兼容端点。它要求每个会话带一个稳定的 `x-opencode-session` 头，用来做路由与提示词缓存亲和；还要求客户端自报 `User-Agent`，而不是露出 HTTP 库的名字。yi 之前两样都没发。

**修法**：会话标识取自会话文件头（一条会话内不变，`/new` 之后换新），随每个请求发出，包括压缩用的非流式请求；`User-Agent` 设成 `yi/<版本>`。DeepSeek 官方会忽略这个头，所以不需要按供应商分支。

**怎么确认修好了**：用无效密钥打两次线上接口——不带头是 400 `MissingSessionID`，带头变成 401 `Invalid credential`，说明会话头这一关过了，只剩鉴权。

**学到**：「OpenAI 兼容」只保证请求体和流式格式兼容，头部约定、会话亲和、限额字段都可能各有各的规矩。接一个新网关，先用一个错误密钥把它的错误分层摸清楚，比对着文档猜快。

## 三、现在还缺的

- 语言服务空闲回收没有自动化用例。
- 诊断动作已删除（`lsp` 只剩跳定义与找引用）：它依赖服务器主动推送，等待窗口有竞态，真实使用中偶发「暂时没有诊断」。诊断改由 `bash` 跑 `go vet` 等命令获得。
- 流式输出期间手打的字符会被当作噪声丢弃（包括有意提前输入的下一句）。
- `cmd &` 起的后台进程按设计保留，不会被 yi 收掉；用的人要自己记得清理。
- 还没有 `web_search`、没有记忆、没有多供应商。

## 四、几条总结

1. **错误必须落盘**。屏幕会滚走，文件不会。
2. **测试证明不了体验**。上面一半的问题只有真实终端、真实仓库、真实模型才会暴露。
3. **提示词管不住已经被带偏的历史**，能用代码确定性解决的，就别写成提示。
4. **任何等待都要有上限**：线程、管道、网络、子进程。
5. **按字节处理文本，在中文环境里迟早出事**。
6. **行式界面不能重绘**，所以流式渲染必须「按行缓冲」，代码块要等围栏结束再一次性着色。
