# yi

跑在终端里的编程 agent：一个二进制、一个进程。内置两套供应商预置——OpenCode Go（默认，模型 `deepseek-v4.1-flash`）与 DeepSeek 官方（模型 `deepseek-flash`），一个进程只用其中一套。
它只服务一个使用者，目标是常驻终端、随手切项目，而不是每次开一个新工具。

名字取自《易经》。日常用法：

```sh
cd ~/gp/some-project
yi
```

## 它刻意不做的事

- 不做多角色、多 agent 编排：一次只跑一条对话线。
- 不做记忆、学习、自动检索历史会话。
- 不接多家供应商，不接多个模型；换供应商要改代码，不是改配置。
- 不做全屏 TUI：输入输出逐行打印，重定向到文件也能看。

这些取舍写在 [docs/adr/0001-single-process-single-provider.md](docs/adr/0001-single-process-single-provider.md) 和 [docs/adr/0002-line-oriented-ui.md](docs/adr/0002-line-oriented-ui.md)；术语见 [GLOSSARY.md](GLOSSARY.md)。

## 环境要求

- macOS 或 Linux。
- Rust 1.89 以上（项目用 2024 版语言标准，会话文件锁用到 1.89 稳定的 `File::try_lock`）。
- [ripgrep](https://github.com/BurntSushi/ripgrep)：`grep` 和 `glob` 两个工具直接调用 `rg`，没有它这两个工具会报错。
- DeepSeek API key。
- 可选：`gopls`（Go 语言服务器）、`phpantom_lsp`（PHP 语言服务器），只有用到 `lsp` 工具时才需要。
- 可选：`bat`，用来给代码块着色；没装时代码块以纯文本显示，功能不受影响。

## 安装

```sh
git clone git@github.com:xushuhui/yi.git
cd yi
cargo install --path .
```

`cargo install` 会把可执行文件放到 `~/.cargo/bin/yi`；确认这个目录在 `PATH` 里。

## 配置

配置文件 `~/.yi/config.json`，全部字段可选：

```json
{
  "provider": "opencode-go",
  "model": "deepseek-v4.1-flash",
  "effort": "auto"
}
```

- `provider` 选预置：`opencode-go`（默认）或 `deepseek`。不写就用 `opencode-go`。
- `model`、`base_url` 可覆盖预置里的默认值；`effort` 是推理强度，可选 `auto` / `low` / `high` / `max`，`auto` 表示请求里不发送这个参数。
- **密钥不写进配置文件**，只从环境变量读：`opencode-go` 用 `OPENCODE_API_KEY`，`deepseek` 用 `DEEPSEEK_API_KEY`。配置文件里写了 `api_key` 会被忽略。
- 语言服务器命令固定取 `PATH` 里的 `gopls` / `phpantom_lsp`，不写进配置文件。
- `YI_HOME` 可覆盖数据目录（默认 `~/.yi`）。
- 数据库连接按项目放在 `~/.yi/projects/<项目编码>/db.json`，里面用 profile 区分 dev / test / prod；密码只从环境变量读（默认 `MYSQL_PWD`，也可在 profile 里用 `password_env` 指定变量名），文件里写 `password` 会直接报错。
- 代理只认这两个变量：`YI_PROXY_<供应商>`（如 `YI_PROXY_OPENCODE_GO`）优先，其次 `YI_PROXY`；通用 `HTTPS_PROXY` / `ALL_PROXY` 不读。本机与内网地址、`NO_PROXY` 命中的地址直连。`socks5://` 会直接报错，请写 `http://127.0.0.1:端口`。
- 每个请求都会带 `User-Agent: yi/<版本>` 和 `x-opencode-session: <会话标识>`。后者是 opencode-go 的要求：缺了它接口直接返回 400 `MissingSessionID`；DeepSeek 官方会忽略它。

## 用法

```sh
yi          # 有历史就接着上次，没有就新开一条
```

`yi` 没有别的开关：同一目录下存在会话文件就打开它继续，不存在就新建一条。启动时打印供应商、模型和会话文件路径，然后把上次的对话放出来——最近三轮，只有你的原话和回答正文，被压缩掉的更早内容不显示，超过两百行只留最近的；你的话按输入区块的样子显示（同样的底色和边距），和下面的回答一眼分得开；只在真终端里放，管道和重定向不受影响。之后进入 `> ` 提示符，输入一句话回车即可；Ctrl-D 退出。提示符连同这一行铺一层深灰底色，把你的话圈成一块，和下面的回答分开。

终端里输入由行编辑器接管：上下键翻当前会话的历史（最近 200 条，连续重复只留一条），左右键移动光标，Home/End、Ctrl-A/E 可用。

等待回复时也能接着打字：敲进去的字会挂在状态行行尾（`等待模型 3.2s · > 帮我看看…`），不会打断这一轮；一轮结束时这些字预填到提示符，你看一眼、改一改，按回车才发。这一轮里回车不会提交，也别指望它——它只是提醒你「这些都还在」。

回车之后如果还没有内容可看（等模型响应、命令正在跑），输入行的位置会有一行淡色状态：`等待模型 3.2s`、`思考中 1.1s`、`运行 bash 12.4s`。它原地刷新、秒数在走，正文一来就擦掉，不留在历史里。只在标准输出是终端时出现；管道和重定向时一个字节都不写，输出保持原样。

以 `/` 开头时按 Tab 补全：输入行下方弹出一块菜单，左边是候选名、右边是说明；继续打字，菜单原地收窄（不会往滚动区追加），上下键选择、回车选定，再回车才提交。没有行内灰字。`/skill:` 后面按同样规则补技能名（冒号后有没有空格都行）；`/effort ` 补 `auto` / `low` / `high` / `max`；`/switch ` 补两个供应商。匹配是子序列式的，`/nw` 能命中 `/new`，`dvrs` 能命中 `adversarial-review`，`/skill: doc` 能命中 `grill-with-docs`；匹配不上任何前缀时只给最匹配的一条。一次最多列 8 条。

从管道或脚本喂输入时（`echo "..." | yi`）不接管按键，行为与以前一致：逐行读取。

想让模型看图，把图片路径贴进来就行——整行是一个路径，或在正文里写 `@路径`（拖拽图片到终端产生的也是路径文本）。支持 png / jpg / jpeg / gif / webp，超过 20 MB 会拒绝。终端会先打一行 `图片：<路径>`，让你确认贴对了。

输入行里按 `Shift+Tab` 切换计划模式：提示符从 `> ` 变成 `plan> `，工作树只读，再按一次回来。这和 Claude Code、Gemini CLI 的「循环权限模式」是同一个手感；切换不会丢掉已经敲了一半的字。

截图后不想存文件，按 `Ctrl-G`：输入行里插入一个 `[图片]` 标记，**提交那一刻**才去读剪贴板里的图片，落到 `~/.yi/clipboard/` 并换成图片附件；剪贴板里没有图片就打一行提示、这一轮只发文字。`Cmd-V` 仍然是终端自己的文本粘贴，两者互不影响——终端不会把 `Cmd` 组合键交给程序，所以图片没法绑在 `Cmd-V` 上。只贴图不写字也行，会自动补一句「看看这张图片里有什么。」。

在 Rex 终端里，yi 还会用 OSC 7501「程序状态协议」上报自己在干什么：干活时没聚焦的标签页头上转圈，一轮结束留下完成标记，Rex 的会话列表里因此能看出哪个标签有新结果。完成标记在退出 yi 之后仍然保留——协议就是为「人还没看」设计的；下一次开始干活时会被 `working` 覆盖。按 Ctrl-C 取消本轮则回到闲置。这套协议只有支持的终端会处理（目前是 Rex），Ghostty、iTerm 这类终端按协议直接忽略，所以没有开关、也不用配置；管道和重定向时一个字节都不发。

终端标题也写着同样的状态，格式是 `yi ⠋ <项目名>`：干活时是转圈的盲文点，轮到你时变成 `>`，这一轮失败是 `!`。Rex 的标签页把标题直接当名字显示，所以在会话列表里就能看到；Ghostty 的标题栏也一样。这套和上面的状态协议互不影响——一个给终端画图标，一个给人直接读。

## 输出长什么样

模型的回答按 markdown 渲染：标题加粗上色，列表换成圆点，引用画成竖线，行内代码反色显示，链接后面跟一个暗色的地址。表格保留原样，只把分隔线调暗——中英文混排重新对齐容易算错宽度。

代码块会等模型写完整个围栏再显示，整块交给 `bat` 着色，头上带一行语言标签：

```
── go ──
func main() { ... }
```

命令里带 heredoc（`cat > x.py <<'EOF' … EOF`、`python3 - <<'PY'`）时，正文按解释器、目标文件后缀或结束标记推断语言，整段交给 `bat` 高亮，和 omp 一样。

代码本身不加任何前缀，复制粘贴不受影响。平时不打印工具调用：读哪个文件、改了哪个文件、跑了哪条命令，屏幕上都看不见，只有状态行里一闪而过的工具名。工具失败时才打一行红色原因，并且带上命令或文件，例如 `✗ bash grep -n zzz nope.txt — 退出码：2`。所有这些照旧完整写进会话文件，事后排查随时能翻。搜索类命令（`grep` / `rg` / `git grep`）没找到东西时打一行暗色的 `bash 没有匹配（退出码 1）`，既不算失败，也不会累加「连续失败三次就停」的计数；`grep` 真正出错（退出码 2，比如文件不存在）仍按失败处理。

颜色只在标准输出是终端时开启。重定向到文件、或设置 `NO_COLOR=1` 时，输出原样透传，不含任何转义序列。

斜杠命令：

| 命令 | 作用 |
| --- | --- |
| `/new` | 把当前会话归档、开一条新的 |
| `/plan` | 切换计划模式：工作树只读，只能查看和调查；再敲一次退出 |
| `/db [profile]` | 不带参数：显示数据库配置路径、当前环境和可选环境；带参数：切换环境（记在会话里） |
| `/effort <档位>` | 切换推理强度：`auto`、`low`、`high`、`max` |
| `/switch <供应商>` | 换供应商与模型：`opencode-go`、`deepseek`；记在本会话，重开仍然生效 |
| `/skill:<名字> [要求]` | 手动调用某个技能，把它的正文注入这一轮 |
| `/help` | 显示命令、环境变量和配置字段 |

### 数据库：一个项目一份，按环境切

配置在 `~/.yi/projects/<项目编码>/db.json`，不进你的工作仓库：

```json
{
  "default": "dev",
  "profiles": {
    "dev":  { "host": "127.0.0.1", "user": "fm", "database": "fm_dev" },
    "test": { "host": "10.0.0.8", "port": 3307, "user": "fm", "database": "fm_test",
              "password_env": "MYSQL_PWD_FM_TEST" }
  }
}
```

`/db` 看当前连哪、有哪些可选；`/db test` 切过去，重启 yi 仍然记得。模型只能看到当前 profile，换环境由人决定。

### 一个项目一条会话

会话按「启动时所在目录的绝对路径」区分，精确匹配：

- 在项目根启动 → 一条会话；在它的子目录启动 → **另一条**会话。
- 进程崩溃（panic）时，崩溃原因和代码位置会作为一条 `notice` 写进会话文件，事后直接 grep 就能看到。
- 中断或崩溃留下的半截工具调用会自动修：尾巴上的补一条「没有执行」，中间的整条回合丢弃，不会让下一次请求被供应商以 400 拒绝。
- 会话文件固定在 `~/.yi/sessions/<目录编码>/session.jsonl`，一条会话就是这一个文件，追加写、不分叉。
- `yi` 永远续写同一个文件，所以不需要"结束会话"。想从头开始就 `/new`，旧文件会改名归档。

### 上下文与压缩

每轮结束只打印一行：

```
[~/gp/yi main · 12% · 缓存 87% · OpenCode Go · DeepSeek V4.1 Flash]
```

- 依次是：项目路径（家目录缩写为 `~`）、当前 git 分支、上下文占比、缓存命中率、供应商、模型。分支取不到时省掉那一段；缓存命中率按本轮累计的输入算（命中 ÷（命中 + 未命中）），没有输入时省掉。
- 占比是最后一次请求的输入 token 占模型窗口的百分比。窗口是 1,048,576（官方文档里俗称的 1M，精确值是 2 的 20 次方，且输入与输出合计），两套预置服务的是同一个模型版本，数字相同。
- 输入超过窗口的 50%（524,288 token）时，本轮结束后自动把最早的一段对话压成摘要，只保留最近约 20,000 token 的原文，然后继续。压缩对使用者无感，但会让前缀缓存失效一次——这是丢掉历史本身决定的。压缩请求自己则复用主请求的前缀：系统提示和要压缩的那段历史逐字节照抄，压缩要求只放在最后一句。
- 每轮的实际用量（未缓存输入、缓存命中、输出）仍然写进会话文件，只是不再显示在屏幕上。

## 工具

模型只拿到八个工具。所有路径都相对项目根（启动目录）。

| 工具 | 做什么 |
| --- | --- |
| `read` | 读文本文件（带行号和内容校验锚点），或列目录一层；也接受图片路径（png/jpg/jpeg/webp/gif，≤ 20 MB），图片直接作为输入发给模型 |
| `write` | 新建或覆盖文件，自动创建父目录 |
| `edit` | 按行号打补丁，只能改这次会话里真正读过的行 |
| `bash` | 在项目根执行 shell 命令（可用 `cwd` 换目录），返回合并后的输出尾部，默认 300 秒超时；`cmd &` 起的后台进程不会拖住返回；带 `background: true` 时命令丢后台立刻返回，跑完的输出在下一轮对话开始时自动带上（同时最多 3 条，退出 yi 时一起杀掉） |
| `grep` | 正则搜内容，返回 `文件:行号:内容`；底层是 `rg`，固定跳过 `node_modules`、`target`、`vendor` |
| `glob` | 按文件名通配查找；底层是 `rg --files`，遵守 `.gitignore`，同样固定跳过 `node_modules`、`target`、`vendor` |
| `lsp` | 查 Go/PHP 的跳定义、找引用 |
| `db_query` | 对 MySQL 跑只读查询（`SELECT` / `SHOW` / `DESCRIBE` / `EXPLAIN` / `WITH … SELECT`），结果按制表符分隔、最多 200 行；连哪个库由本项目的配置文件和当前 profile 决定，密码取自环境变量。写操作工具层直接拒，改数据请用 `bash` |

一轮对话不限制总步数：只要每次调用有变化就继续做，长任务不会被步数掐断。但如果同一个调用（工具名和参数完全相同）连续失败 3 次，会停止调用工具，让模型说明现状后再结束——这是唯一会自动中断的情况。

### 锚点：为什么 `edit` 不会改错行

`read` 返回的第一行长这样：

```
[src/main.rs#1A2B]
```

`#1A2B` 是根据整个文件内容算出的 4 位十六进制锚点。之后 `edit` 必须带同一个锚点：

```
[src/main.rs#1A2B]
PUT 12.=13:
+func main() {}
+
```

文件在这期间被别的程序改过，锚点就对不上，`edit` 会拒绝并要求重新 `read`。补丁语法只有四种：`PUT N.=M:` 替换第 N~M 行、`PUT <N:` 在第 N 行前插入、`PUT >N:` 在第 N 行后插入、`CUT N.=M` 删除第 N~M 行。

### 语言服务（LSP）

- 支持 `.go`（`gopls`）、`.php`（`phpantom_lsp`）和 `.rs`（`rust-analyzer`），其它扩展名直接报错。
- 按「语言 + 项目根」懒启动：第一次调用才起进程，项目根是最近的 `go.mod` / `composer.json` / `Cargo.toml` 所在目录。
- `rust-analyzer` 在建索引前会返回空结果，yi 会自动重问最多 30 秒；首次查定义可能要等一两秒。没装的话提示 `rustup component add rust-analyzer`。
- 后台每 60 秒清一次，空闲超过 10 分钟的服务器会被终止；`yi` 退出时全部终止；服务器自己崩了，下次调用自动重起。
- 两个动作：`definition`、`references`，都要给行号（从 1 开始）。
- 单次请求 15 秒超时，超时作为普通错误文本返回给模型，不会卡住终端。

## 系统提示词、AGENTS.md 与技能

- 系统提示词在 `prompts/system.md`，编译时内嵌进二进制，是唯一来源。
- 启动时再追加两份 `AGENTS.md`（如果存在）：`~/.yi/AGENTS.md`（用户级）和仓库的 `AGENTS.md`，以 `<context-file>` 块原样拼在后面。仓库那份从启动目录**往上找最近的**，到家目录为止——所以在子目录启动也能用上仓库根的规则。
- 系统提示词里写明了：这些块是必须遵守的规则，与当轮要求冲突时先问清楚。
- 技能是带 YAML 头部的 `SKILL.md`，扫描顺序：`<项目>/.yi/skills`、`~/.yi/skills`、`~/.agents/skills`。
  - 系统提示词里只列技能的名字、描述和路径，模型需要时用 `read` 读正文。
  - 头部写 `disable-model-invocation: true` 的技能不出现在提示词里，只能由人用 `/skill:<名字>` 调用。

## 开发

```sh
cargo test          # 单元 + 集成测试；集成测试用本地假服务器代替 DeepSeek
cargo clippy --all-targets
cargo fmt
```

- `src/agent.rs` 是核心：一轮对话的循环、工具分发、压缩。
- `src/provider.rs` 是 DeepSeek 的流式 HTTP/SSE 客户端。
- `src/tools.rs` 是八个工具的实现；`src/lsp.rs` 是语言服务器客户端。
- `src/session.rs` 负责 JSONL 会话文件的追加与重建。
- 第一期规格与验收用例在 [.scratch/yi-phase-1/spec.md](.scratch/yi-phase-1/spec.md)。
- 当初为什么这么设计、开发中踩过哪些坑，见 [docs/dev-notes.md](docs/dev-notes.md)。

LSP 的集成测试需要本机装了 `gopls` / `phpantom_lsp`；缺哪个就打印 `SKIP` 并返回，不算失败。
