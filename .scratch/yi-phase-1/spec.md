# yi 第一期规格

Status: ready-for-agent

## 问题陈述

我现在用 omp 做日常开发，它在三个方面拖慢我：**内存**——此刻机器上跑着 15 个 omp 进程，合计约 1.5 GB 常驻内存，单个界面进程最高 358 MB，安装包 199 MB，会话数据目录 531 MB；**功能**——它的大部分能力我从未使用，真正每天用的只有五个动作：读文件、改文件、执行命令、搜索、写文件（占我 39,886 次工具调用里的 90.7%）；**会话模型**——omp 逼我结束一个会话再开一个，同一批项目反复回来时，39 个项目攒出了 181 个会话，上下文不断断裂。

我要的是一个我自己的工具：启动即用的单二进制终端 agent，只服务我这台 Mac、只接 DeepSeek 一个模型、只做我每天真正在做的六件事，一个项目一条会话线，改代码时有防呆保护（不允许凭想象改没读过的行），界面中文，随我日常使用逐步长功能。

## 解决方案

`yi` 是一个 Rust 写的单二进制终端程序。在项目目录敲 `yi`，直接接上这个项目上一次的对话继续干活；想换话题敲 `/new`，旧会话被归档、新会话开始，不用退出重开。它把回答逐字打印到终端，一轮结束后打印一行页脚（上下文占用、缓存命中率、本轮 token），然后等你输入下一句——终端自己的滚动、搜索、选中复制全部照常可用。

它能读文件（带行号和内容校验锚点）、改文件（只能改这次真正看过的行，文件被别人动过会拒绝）、写文件、执行 shell 命令、按正则搜索代码、按通配符找文件，也能把图片作为输入发给模型。上下文涨到模型窗口的 50% 时，它自动把最早的一段对话压成摘要，只保留最近约 20,000 个 token 的原文，所以我永远不需要主动结束会话。

它内置两套供应商预置（OpenCode Go 与 DeepSeek 官方），默认用 OpenCode Go 的 `deepseek-v4.1-flash`，配置文件里一句话就能换（这不是多供应商抽象，只是一张两行的预置表，见 ADR-0006）；密钥只从环境变量读，配置文件不保存密钥。系统提示词是中文，会读取用户级和仓库级的 `AGENTS.md`。第一期不做记忆、不做多模型、不做子 agent、不做任何我没要求的通用性。

## 实现决策

### 进程与启动

- 单个 Rust 二进制，名字 `yi`，单进程，**不引入异步运行时**。网络请求用阻塞客户端加一条读线程，工具调用与模型请求都用线程和通道协作。否决 `tokio`：单人单会话的循环里它只带来依赖和心智负担。
- 命令行参数只有两个：`-h`、`-v`。否决 `clap`：两个参数用标准库 `std::env::args` 足够。否决 `-c`：默认行为本来就是「有历史就继续、没有就新建」，保留一个同义开关只会让人以为存在「不继续」的另一种模式。
- `yi` 的默认行为是**打开或创建当前工作目录对应的会话**（第 8 轮确认：默认继续）。否决“默认新会话”：会重现 omp 那种同一项目攒出十几个会话的毛病。
- 项目的身份是**规范化后的当前工作目录的绝对路径，精确匹配**。在子目录启动算另一个项目。否决“向上查找 git 根”：多一层猜测，且和你的习惯（永远在项目根启动）不符。
- 同一项目同时只允许一个实例：进程启动时对会话文件加排他锁（Rust 标准库 `std::fs::File::try_lock`，1.89 起可用，已在 1.99.1 实测通过），拿不到锁就打印提示并非零退出。

### 依赖底线

直接依赖上限 6 个，按里程碑分批引入。当前 4 个，`cargo tree` 实测（macOS、Rust 1.99.1）合计 78 个包（含项目自身）：

| 依赖 | 引入时机 | 用途 | 为什么不能用标准库 |
|---|---|---|---|
| `serde` + `serde_json` | 里程碑 ① | JSON 序列化与解析 | 标准库没有 JSON |
| `ureq`（rustls 后端） | 里程碑 ① | HTTPS 请求与流式响应体 | 标准库没有 TLS |

`ratatui` 与 `crossterm` **第一期不引入**：界面先走行式输出，理由见 ADR-0002。真需要全屏时再加，那时合计约 80 个包。否决的全屏方案对比（同样实测）：加 `ratatui` + `crossterm` 是 80 个包；再加 `tokio` + `reqwest` + `clap` 是 168 个包，比 omp 的依赖规模还大。开发依赖只有 `parking_lot`（工具规则要求在测试里用它替代 `std::sync::Mutex`）；测试用的假服务器仍用标准库 `TcpListener` 手写，不引入网络库。

### 会话存储

- 位置：`~/.yi/sessions/<编码后的项目路径>/session.jsonl`。编码 = 绝对路径把 `/` 换成 `-`（中文原样保留），末尾追加路径的 8 位十六进制哈希，兼顾可读与唯一。
- 格式：纯文本 JSONL，一行一条。第一行是头：`{"type":"session","version":1,"id","timestamp","cwd","model","effort"}`；其后是 `message`、`compaction`、`effort_change`、`model_change`、`plan_change`、`db_change`、`notice` 七类条目；`notice` 只给人看（失败原因、请求次数达上限、崩溃原因），不进入模型上下文，压缩也不会带走（推理强度与供应商的变更分别追加 `effort_change`、`model_change`，不回改系统消息，也不进入模型上下文）。`model_change` 记供应商 id 与模型 id，重开会话时以最后一条为准，配置文件只作新会话的默认。
- **线性结构，不存 `parentId`，不做树**。否决 omp/pi 的树形条目：分支、fork、会话树全都不做，树形字段就是死重量。
- 每条 assistant 消息记录 `usage`：未缓存输入、缓存命中输入、输出、推理强度、耗时。
- 流式输出过程中不落盘；一条消息完成后追加一次。进程崩溃最多丢当前这一条。
- `/new` 把 `session.jsonl` 改名为 `session-<Unix 秒>.jsonl`，然后开始新文件。不删除任何东西。
- 会话文件是可 grep 的纯文本审计记录，也是唯一的持久状态。

### 上下文重建

- 读取头 → 顺序读取全部条目 → 若存在 `compaction` 条目，则摘要作为一条 user 消息放在最前，其后只保留 `firstKeptSeq` 之后的消息。
- 丢弃没有配对工具结果的 assistant 消息（流中断或被杀）以及孤立的工具结果，避免请求被供应商拒绝。
- 模型与推理强度的变更以追加条目的形式记录，**不回改系统消息**，以保证前缀稳定。

### 压缩

- 触发判据用供应商返回的真实用量：最近一次响应的 `prompt_tokens` 超过**当前模型上下文窗口的 50%**时，在本轮结束后压缩。窗口跟着预置走。两套预置服务的是同一个模型版本（V4.1-Flash-1017），官方文档给的精确窗口是 **1,048,576**（即俗称的 1M，输入与输出合计），所以阈值都是 524,288。否决本地估算触发：供应商已经给了准确数字，估算是多余误差源。
- 切点：从最新消息往回累计，保留不少于 **20,000 个 token** 的原文（按 UTF-8 字节数除以 3 估算），且必须切在 user 消息的边界上。否决在工具结果处切：供应商要求工具调用与结果配对。
- 摘要用同一个模型发一次非流式请求：请求的系统提示与历史（含上一份摘要）和主请求逐字节相同，压缩要求（`prompts/compaction.md`，编译期内嵌，要求中文输出九节）作为最后一句用户消息追加——这样前缀缓存能命中，只有指令那段 token 要重算。摘要本身产生的 token 不进入会话上下文，只写入日志。
- 为什么是这九节：前六节保证接续，后三节解决压缩后最常见的两种退化——把否决过的方案重新提出来、丢掉"试过什么、为什么不行"。
- **不**把 retro 的内容写进摘要：retro 是给人改环境用的，进了摘要会变成模型的额外任务；而且它需要完整对话，压缩时那段对话正好要被丢弃。
- 压缩条目形如 `{"type":"compaction","summary","firstKeptSeq","tokensBefore"}`。摘要消息在重建时包在 `<compaction-summary>` 里。
- 中断或崩溃可能留下「助手消息带 tool_calls、但没有对应工具结果」的半截回合。供应商要求两者严格配对，所以：尾部缺口在启动时补一条 `ERROR: 上一轮被中断…` 的工具结果；中途缺口在构造上下文时整条丢弃（连同它那几条孤立工具结果）。
- 压缩会使前缀缓存失效一次，接受这个代价。

### 供应商

- 两套预置，一个进程只用其中一套：
  | 预置 id | 地址 | 默认模型 | 窗口 | 密钥环境变量 |
  |---|---|---|---|---|
  | `opencode-go`（默认） | `https://opencode.ai/zen/go/v1` | `deepseek-v4.1-flash` | 1,048,576 | `OPENCODE_API_KEY` |
  | `deepseek` | `https://api.deepseek.com` | `deepseek-flash` | 1,048,576 | `DEEPSEEK_API_KEY` |
- 请求：`POST <预置地址>/chat/completions`，`stream: true`，`stream_options: {"include_usage": true}`。两者都是 OpenAI 兼容协议，走同一份代码。
- **密钥只从环境变量读**，配置文件里的 `api_key` 一律忽略：配置文件会被同步、备份、误提交。缺密钥时报错信息点名该供应商的环境变量。
- 代理：启动时解析一次，一个进程只用一个代理。顺序是先判「本机回环与内网私有地址」直连，再判 `NO_PROXY` / `no_proxy`（支持 `*`、`.example.com`、`*.example.com`、带端口写法），命中就直连；否则取 `YI_PROXY_<供应商>`（供应商 id 大写、标点换下划线，例如 `YI_PROXY_OPENCODE_GO`），再退到 `YI_PROXY`。**不读通用的 `HTTPS_PROXY` / `ALL_PROXY`**：那些变量一旦指向较慢的线路，会拖慢每一次请求，而且和别的工具互相牵连。地址写成 `socks5://…` 时启动即报错，不静默退回直连——ureq 的 SOCKS 支持需要额外编译开关，当前不开。
- 两个请求头，所有请求（含压缩用的非流式请求）都带：`User-Agent: yi/<版本>`（供应商要求客户端自报家门，而不是露出 HTTP 库名）；`x-opencode-session: <会话标识>`（opencode-go 按它做路由与缓存亲和，缺了直接返回 400 `MissingSessionID`；DeepSeek 官方忽略这个头）。会话标识取自会话文件头，一条会话内不变，`/new` 之后换新。
- **永不发送 `tool_choice`**：DeepSeek 在思考模式下会因此返回 400。
- assistant 的工具调用轮必须把 `reasoning_content` 原样回放，否则供应商拒绝或行为异常；该字段随消息存进会话文件。
- 推理强度映射：`auto` = 不发送 `reasoning_effort`（由服务端默认 high）；`low` / `high` / `max` = 原样发送。两个模型的元数据都只列出这三档。
- 缓存：历史前缀只追加、不改写；系统提示词在一条会话内不变；工具结果按顺序追加。用量映射：缓存命中 = `prompt_cache_hit_tokens`，未缓存输入 = `prompt_cache_miss_tokens`，输出 = `completion_tokens`。
- 重试：连接错误、5xx、429 退避重试 3 次（1s / 2s / 4s）；4xx 立即报错并保留原始信息。连接超时 10 秒，读空闲超时 120 秒。
- SSE 解析：按行读取，取 `data: ` 之后的内容，`[DONE]` 结束；`tool_calls` 按 `index` 累积参数片段，流结束时统一解析成 JSON 交给工具层。

### 工具

八个工具，输入都是扁平 JSON 对象。返回值对模型可见，长度统一截断为 2,000 行或 50 KB（先到者为准）。

**`read { path, offset?, limit? }`**
- 文本：返回头部 `[相对路径#TAG]`，随后每行 `行号:内容`。`TAG` 是文件内容摘要的 4 位大写十六进制。默认 300 行，单次上限 3,000 行；没读完时在末尾给一行「共 N 行，用 offset=X 继续读」。
- 目录：列出一层，目录名带尾斜杠。
- 图片（png/jpg/jpeg/webp/gif，≤ 20 MB）：作为图片内容块返回，不输出文本。
- 每次返回都把「路径 → (TAG, 已显示行集合)」记进本会话的快照表。

**`edit { input }`**
- 补丁文本，每段以 `[相对路径#TAG]` 开头，操作三种：
  - `PUT 起始行.=结束行:` 后跟若干 `+` 开头的最终内容，替换该区间；
  - `PUT <行号:` 在该行前插入，`PUT >行号:` 在该行后插入；
  - `CUT 起始行.=结束行` 删除。
- 校验四条：TAG 必须等于当前文件内容；每个操作涉及的行必须都在快照的已显示行集合里；同一补丁内区间不得重叠；结果不得与原文完全相同。
- 多段补丁里有多个文件时：**先全部校验、算出结果，全部通过才写盘**；任何一处失败都不改动任何文件。同一文件的多个段落合并成一次校验。
- 通过后写盘，返回新的 `[路径#TAG]` 和一行改动摘要。快照只把「补丁产生的行」和「原来读过、按行号映射到新位置的行」标为已读，**不**把整个文件标为已读。
- 容错两条（照 omp 的容错范围）：正文行漏写 `+` 时自动补上并在结果里提示；接受 `*** Begin Patch` / `*** End Patch` 信封。真正写坏的补丁仍然报错，文件不变。
- 不支持：命名寄存器、跨文件移动、语法块锚点、`apply_patch` 模式。否决这些：都是 omp 为通用场景加的，日常改码用不到。

**`write { path, content }`**：建父目录、覆盖写、返回新的 `[路径#TAG]`。

**`bash { command, cwd?, timeout?, background? }`**
- 命令开头若写 `cd <项目根> && `（含带引号的写法），执行前直接剥掉：项目根本来就是工作目录，剥掉语义等价，也免得绝对路径占满整行；指向别的目录的 `cd` 原样保留。
- 命令里用 `&` 启动的后台进程不会阻塞返回：shell 退出后最多再等 300 毫秒收输出快照，后台进程继续运行，其后续输出不再属于这一轮。
- 工作目录默认项目根；可用 `cwd` 指定（相对路径按项目根解析，绝对路径原样使用，必须是已存在的目录）。工具说明里写明"命令已在项目根，不要写 `cd`"，让模型用参数而不是前缀。默认超时 300 秒，上限 3,600 秒。
- 输出边读边写日志、内存里只留最后 50 KB（stderr 同样最多 50 KB），完整日志在 `<会话目录>/logs/<序号>.log`，结果里给出路径。stderr 单独收集后再拼接，**不**在命令串里追加 `2>&1`——那样会覆盖用户自己的重定向。
- 结果末尾必须带 `退出码：N`；被信号终止时写“被信号终止”，不能留空。
- 超时先向整个进程组发 TERM，300 毫秒后补 KILL，保证孙进程也退出、管道关闭（否则收集线程会一直等）。

**`grep { pattern, path?, glob?, case? }`**
- 底层调用外部 `rg`（ripgrep），不内置正则引擎：`rg` 速度快、自带 `.gitignore` 与二进制文件处理，省去一个依赖。未安装时报错提示需要 ripgrep。
- 遍历时固定排除 `node_modules`、`target`、`vendor`（经 `rg --glob '!dir'` 实现，`glob` 工具同样排除）。
- 命中行按 `相对路径:行号:内容` 返回，单文件最多 20 条、总量最多 200 条，每行截断到 512 字符。
- 输出里的行号和文件内容同样进入快照表，可以直接拿去 `edit`；同一锚点下再次 `read`/`grep` 会把新看到的行**并入**旧记录，不是覆盖。
- 命中文件超过 **4 MB** 时不为它记快照（读整份文件只为算锚点，代价太高）；要改这种文件，先 `read`。

**`glob { pattern, path? }`**
- 通配符相对**给定的搜索根**匹配（`path=src` 配 `*.go` 命中 `src/a.go`），跳过同上的目录，按修改时间倒序，最多 200 条。

**`lsp { action, path, line?, symbol? }`**
- `action` 二选一：`definition`、`references`；其余动作直接报错，且**在校验通过前不启动服务器**。
- 必须给 `line`（从 1 开始），`symbol` 省略时用该行第一个非空白字符的列。
- 只接受 `.go`、`.php` 和 `.rs`；其余扩展名报错。缺少服务器时的报错点名命令，Rust 还附带 `rustup component add rust-analyzer`。
- 输出：`文件:行:列  代码片段`，每条一行。`definition` 最多 10 条、`references` 最多 50 条；超出时在末尾写"还有 N 条未显示"。
- URI 按百分号编码传输并解码，中文、空格、`#`、`%` 等路径必须能正确往返。

**`db_query { sql, database?, timeout? }`**
- 只读：只接受 `SELECT`、`SHOW`、`DESCRIBE`、`DESC`、`EXPLAIN`、`WITH … SELECT`；分号拼接多条直接拒，`INTO OUTFILE` / `INTO DUMPFILE` 直接拒，`WITH` 的主语句必须是 `SELECT`。写操作留给用户明确批准后的 `bash`。
- 连接信息按项目放在 `$YI_HOME/projects/<项目编码>/db.json`，用 `profiles` 区分环境，`default` 指定默认；工具只用当前 profile，模型不能自己选环境。密码只从环境变量读：profile 的 `password_env` 或默认的 `MYSQL_PWD`；文件里出现 `password` 直接报错。缺配置时错误信息给路径与样板。
- 用系统 `mysql` 客户端以 `--batch --raw` 执行，SQL 从标准输入喂进去（不进命令行、不进日志里的密码位）；默认 15 秒超时，按进程组终止。
- 结果按制表符分隔，最多 200 行（表头另算），超出时末尾提示截断。

### 终端界面

- **行式模式**，不做全屏。输出直接打印到终端，一轮结束后等一行输入。终端的滚动、搜索、选中复制全部照常可用，不用自己实现。否决 `ratatui` 全屏：为了常驻一行状态栏，就要自己重做滚动、翻页、缩放、复制，还要接管终端原生能力（见 ADR-0002）。
- **markdown 渲染**（见 ADR-0004、ADR-0007）：按行渲染标题、列表、引用、行内代码、链接；表格攒齐后按显示宽度对齐（不画竖线、列间两个空格、表头下一条暗色分隔线，`:---:` 居中、`---:` 右对齐），总宽超过终端列数时先按列收缩、把每格按显示宽度折行（不切开行内标记，粗体与行内代码整段作为折行单位），仍放不下才回退原样；代码块攒到结束围栏后整块交给 `bat` 着色（`--style=plain --theme=ansi`），没装 bat 就退化成无色。只在标准输出是终端且未设置 `NO_COLOR` 时着色，其余情况原样透传。工具失败打一行红色原因（前缀 `✗`，带工具名和命令/文件，例如 `✗ bash grep -n zzz nope.txt — 退出码：2`）；成功的工具不额外打印，`edit` 的改动清单与新锚点只写进会话，供模型下一轮读取。搜索类命令（`grep`/`rg`/`git grep`）退出码为 1 表示「没找到」：工具返回 `没有匹配（退出码 1）`，界面打一行暗色提示，不计入连续失败；退出码 2 仍算失败。
- 流式文本逐字打印；思考内容默认隐藏。没有输出的时候，输入行位置有一行处理中状态（`等待模型 3.2s` / `思考中 1.1s` / `运行 bash 12.4s`），回车回到行首原地重画，最多每 200 毫秒一次；有正文、工具调用、工具结果或提示要打印时先擦掉它，不留历史。只在标准输出是终端时出现，管道与重定向里逐字节不变（见 ADR-0009）。这一行同时承载轮内草稿：一轮之内终端关掉回显与行缓冲，按键按字节立即收下，挂在状态行行尾（`等待模型 3.2s · > 你打的字`），宽度不够时只留最新的一段；回车在这一轮里既不提交也不入草稿。
- 工具调用默认不打印：读文件、改文件、跑命令都不占屏幕，只在处理中状态里露出工具名。工具调用与结果照旧完整写进会话文件，供事后排查。
- yi 用 OSC 7501「程序状态协议」把状态报给终端：一轮开始 `working`（msg 跟着状态行走：等待模型 / 思考中 / 运行某工具），成功 `done`（带耗时），整轮失败 `error`，Ctrl-C 取消 `idle`；`done`/`error` 在进程退出后保留（协议要求留给「还没看」的人），下一轮 `working` 覆盖它，不主动清理。只在标准输出是终端时发，不做探测（读回复会和行编辑器抢输入）；Rex 用它画标签页转圈与完成标记，其他终端按协议忽略。
- 同一目录再次启动时，把最近三轮对话重放到屏幕上：用户敲的原文（技能调用不展开）与回答正文；不重放工具调用、工具输出与思考内容。用户那几条按输入区块原样复现（上下边距 + 底色 + 每行补满），多行粘贴时每一行都在块内，和实时输入看起来一致；不着色时退回一行 `> 原文`。只重放压缩边界之后的内容（模型还记得的部分），超过 200 行只留最近并注明省略条数；只在标准输出是终端时重放，管道与重定向里逐字节不变。
- 终端标题同步运行状态（OSC 0）：`yi ⠋ <项目名>` 表示干活中，盲文点每 100 毫秒换一帧；轮到你时 `yi > <项目名>`，这一轮失败 `yi ! <项目名>`。Rex 的标签页直接把标题当名字显示，Ghostty 的标题栏同理；只在标准输出是终端时写。
- 每轮结束只打印一行页脚：项目路径（家目录缩写为 `~`）、当前分支、上下文占比、缓存命中率、供应商、模型，形如 `[~/gp/yi main · 13% · 缓存 87% · OpenCode Go · DeepSeek V4.1 Flash]`。占比是最近一次请求的 `prompt_tokens` ÷ 当前窗口；缓存命中率是本轮累计的 `cache_hit` ÷（`cache_hit` + 未命中输入）。分支每轮跑一次 `git rev-parse --abbrev-ref HEAD`，不是 git 仓库或游离 HEAD 时省掉这一段。本轮 token 用量仍只写会话文件。
- 输入区自成一块：提示符上方一行铺满底色的上边距，提示符与其后的输入继承同一层底色（折行也带着），回车后把最后一行右边补满。底色是用空格写满整行，不依赖终端的「擦除用底色」，所以在不支持该特性的终端上也不会缺一块；只在标准输出是终端且未设置 `NO_COLOR` 时出现，管道与重定向里不加任何字节。
- 输入：标准输入是终端时交给行编辑器（`reedline`，见 ADR-0011）——上下键翻历史、左右移动、退格、Home/End；不是终端时保持逐行读取，供管道和测试使用。Enter 提交，空行忽略，以 `/` 开头按斜杠命令处理。历史是用户敲的原文，存成会话文件里的 `prompt` 条目，最近 200 条、连续重复只留一条，不进入模型上下文。输入行里 Ctrl-C 放弃当前行（编辑器把缓冲区一并交回，直接丢掉），Ctrl-D 退出；Shift+Tab 切换计划模式（等价于 `/plan`），提示符变成 `plan> `，输入到一半的内容保留（编辑器挂起再恢复）；一轮请求或命令执行期间按 Ctrl-C 取消这一轮（请求与读响应在工作线程，主线程每 100 毫秒检查信号标志与终端发来的 0x03）。
- 中断：一轮请求或命令执行期间按 Ctrl-C 取消这一轮，会话保留，回到提示符；这段时间其余按键进轮内草稿（见上一条），轮末预填回提示符，由人按回车决定发不发。输入行里 Ctrl-C 放弃当前行（编辑器把缓冲区一并交回，直接丢掉），Ctrl-D 退出。
- 斜杠命令六个：`/new`、`/plan`、`/db [profile]`、`/effort <auto|low|high|max>`、`/switch <opencode-go|deepseek>`、`/help`。`/db` 不带参数打印配置路径、当前 profile 与可选项；带参数切换并追加 `db_change`，重开仍然生效；模型不能自己换环境。`/plan` 切换计划模式：打开后 `write` / `edit` 直接被拒，`bash` 只放行只读命令（`ls`、`cat`、`rg`、`git log/diff/status`、`go test` 这类），拒绝时回灌一条 `ERROR:` 说明；开关追加 `plan_change`，重开仍然生效，页脚显示 `plan`。`/switch` 换供应商与模型：参数为空时打印当前模型与可选项；密钥缺失当场报错、不切换；切换只影响本会话并追加 `model_change`，重开仍然生效。
- 多行输入：粘贴多行时整段作为一条消息提交，不按行拆开。
- 图片输入（见 ADR-0008）：整行是一个图片路径、或正文里写 `@路径`，该图作为一条图片消息跟着这句话发出，终端先打一行「图片：<路径>」。相对项目根解析，只认存在的 png/jpg/jpeg/gif/webp；不缩放，超过 20 MB 拒绝。
- 补全：Tab 打开菜单，菜单画在输入行下方、原地刷新：左边候选、右边说明，输入继续时按当前内容重算，绝不往滚动区追加。**不做行内灰字**（它只能显示一条，且总画在行尾，光标在中间时会和正文粘在一起）。候选由 `complete::candidates` 计算：以 `/` 开头的按子序列模糊匹配（`/nw` → `/new`），`/skill:<前缀>`（冒号后允许空格）补技能名并带说明（说明截到 90 格），`/switch ` 补供应商，`/effort ` 补四个档位；没有候选以已输入内容开头时只给最佳一条；一次最多 8 条，不再伪造「还有 N 个」的占位行。回车在菜单打开时选定候选，再回车才提交。

### 技能

- 一个技能 = 一个装 `SKILL.md` 的目录。只扫一层，不递归。
- 查找顺序（先找到的同名优先）：项目 `.yi/skills` → 数据目录 `skills` → 数据目录同级的 `.agents/skills`。最后一条是为了复用既有的共享技能目录，不搬动它们。
- 系统提示词里只放 `名字：描述（正文路径）`，正文由模型需要时自己 `read`。会话开始时算一次，保证前缀稳定。
- `disable-model-invocation: true` 的技能不进提示词，只能由用户用 `/skill:<名字> [要求]` 调用；这条命令把正文注入成一条用户消息。
- 缺 `description` 的目录直接跳过（描述是唯一的路由依据）。frontmatter 只解析一层的 `键: 值`，带引号的值去引号。

### LSP（第二期，仅 Go 与 PHP）

- 只用机器上已有的服务器，**不安装新的**。实测：Go 用 `gopls`（v0.21.1，`/opt/homebrew/opt/gopath/bin/gopls`），PHP 用 `phpantom_lsp`（0.8.0，`/opt/homebrew/bin/phpantom_lsp`），Rust 用 `rust-analyzer`（1.99.1，随 rustup 组件安装，`/opt/homebrew/opt/rustup/bin/rust-analyzer`）。
- **不支持 TypeScript**：机器上没有独立的 TypeScript LSP；VS Code 自带的 `tsserver` 在应用包内、走私有协议，要包一层才算 LSP，属于安装新东西，不做。
- 工具面只开两个动作：`definition`、`references`。诊断、悬停、重命名、格式化都不做：诊断靠 `bash` 跑 `go vet` 等命令；它需要等待服务器推送且有竞态，删掉比修更划算。
- 懒启动：第一次调用才起进程，按 (语言, 项目根) 缓存；后台线程每 60 秒清一次，空闲超过 10 分钟的服务器自动终止，yi 退出时一并终止。服务器自己崩了，下次调用自动重起。
- 服务器命令固定取 PATH 里的 `gopls` / `phpantom_lsp`；配置文件里写 `gopls` / `phpantom` 会被忽略，免得同一个东西有两种配法。
- 超时：`initialize` 15 秒（Rust 放宽到 60 秒，它启动后要建索引），单次请求 15 秒；超时以 `ERROR:` 文本返回，不卡住整轮。
- rust-analyzer 在建好索引前会回空数组、`null`，或 `content modified`（-32801）；这三种都当「还没准备好」，每 250 毫秒重问一次，最多 30 秒。其他语言不重试。
- 项目根：Go 找最近的 `go.mod`，PHP 找最近的 `composer.json`，Rust 找最近的 `Cargo.toml`；找不到就用当前目录。

### 提示词与上下文文件

- 系统提示词中文，正文放在仓库的 `prompts/system.md`，编译期内嵌进二进制，是唯一来源。会话开始时组装一次，之后不变。
- 拼接顺序：基础提示词（内嵌）→ 用户级 `~/.yi/AGENTS.md`（存在则拼）→ 仓库级 `AGENTS.md`（存在则拼）。个人偏好只走 `AGENTS.md`，不设整份替换的入口。
- 仓库级文件从启动目录往上找**最近的一个**，到家目录为止：在子目录启动也能用上仓库根的规则，再往上不看，避免捡到别的项目的。
- 两份文件都包在 `<context-file path="…">` 里；基础提示词明确要求把这类块当作必须遵守的规则，与当轮要求冲突时先问。
- 不做 `@` 导入、不做 `RULES.md`、不做多来源发现（omp 有 18 个来源，我们只有 2 个）。文件改动在下次启动生效，不热加载——保证缓存前缀稳定。

### 错误处理

- 工具失败不抛异常、不中断循环：把 `ERROR: <原因>` 作为工具结果返回给模型，让模型自己决定重试还是换路。
- 一轮对话**不设总请求上限**：总步数限制会把「活多」误判成「死循环」——真实任务里删一个接口就用满了 41 步（`fm-openapi` 会话 2026-11-12）。防死循环改用「同一个调用（工具名 + 参数完全相同）连续失败 3 次」判定：停下、写一条 `notice`，再给模型一次不带工具的机会说明现状（改了什么、为什么卡住、还剩什么），然后正常结束。依据是 omp 的同类机制（"tool-call loop limits … to prevent repeated failing calls from continuing without bound"）与 pi 的无上限循环。
- 供应商错误直接打印在终端并保留本轮的用户消息，不回滚会话。
- 任何路径都不 `panic`；配置缺失、密钥缺失给出明确的中文提示并非零退出。

## 测试决策

**唯一接缝：agent 核心的 `submit` 入口。** 二进制只是一层薄壳，核心逻辑放在库中；测试是集成测试，直接调用库的 `submit(prompt)`，传入临时工作目录，供应商指向本地假服务器（测试内用标准库 `TcpListener` 手写 HTTP/1.1 + SSE，约 150 行）。否决通过伪终端驱动整个界面：那会引入终端字节流解析和偶发失败，而界面层没有值得这样测的独立逻辑。否决为纯函数（锚点解析、压缩切点）单独开接缝：它们都能从这一个入口触达，多一个接缝就多一处可以和行为脱节的地方。

**好测试的标准**：只断言外部可见的结果——工作区文件内容、会话 JSONL 里的条目、假服务器记录到的请求体、退出码和错误文本。不断言内部函数调用次数、不断言结构体字段、不测「调用了哪个模块」。

**用例清单**（每条都是「输入 → 期望」）：

1. `read` 一个文件 → 输出含 `[路径#TAG]` 与 `行号:内容`；文件改动后再读，`TAG` 变化。
2. 对读过的行 `edit` → 文件内容正确，返回新 `TAG`。
3. 对没读过的行 `edit` → 返回 `ERROR`，文件字节不变。
4. `read` 后从外部改动文件，再 `edit` → 返回 `ERROR`，文件保持外部改动后的样子。
5. 同一补丁重复提交 → 第二次返回 `ERROR`。
6. 工具返回 `ERROR` 后循环继续 → 假服务器收到的下一轮请求里含该错误文本作工具结果。
7. `bash` 输出超过 50 KB → 返回值只有尾部，完整日志文件存在且长度为全部输出。
8. `bash` 超时 → 返回 `ERROR`，子进程已退出。
9. `bash` 带 `background: true` → 立刻返回「已转入后台：bash-N」，这一轮不等命令；命令跑完后的输出在下一轮开始时作为一条用户消息写进会话，界面上打一行「后台作业 bash-N 完成」；同时最多 3 条，超出拒绝；退出 yi 时把还在跑的后台进程整组杀掉。
9. 第二轮请求的 messages 前缀与第一轮逐字节相同；assistant 工具调用轮的 `reasoning_content` 出现在下一轮请求中。
10. `/effort` 设为 `low` → 请求体含 `"reasoning_effort":"low"`；`auto` → 请求体不含该键。
11. 输入行按 `Shift+Tab` → 提示符变成 `plan> `，会话追加 `plan_change`；再按一次变回 `> ` 并追加一条 `false`；按到一半的字不丢、不重复。
12. `/plan` 打开后模型调 `write` → 工具结果以 `ERROR:` 开头、文件不存在；调 `bash "echo hi > out.txt"` → 同样被拒；`bash "git diff"` 正常执行；再敲 `/plan` 关闭后 `write` 落盘。页脚含 `plan`，重开同一条会话仍是计划模式。
11. 假服务器返回带大 `prompt_tokens` 的用量，超过当前窗口的一半（`deepseek` 预置下是 524,288）→ 会话文件追加 `compaction` 条目；下一次请求只含摘要与 `firstKeptSeq` 之后的消息。
12. 同一目录启动第二个实例 → 非零退出，提示已存在运行中的会话。
13. `/switch deepseek`（`DEEPSEEK_API_KEY` 已设）→ 会话追加 `model_change`，横幅与页脚变成 DeepSeek；重开同一目录仍是 DeepSeek。`DEEPSEEK_API_KEY` 未设 → 打印缺密钥、会话里不追加条目。
14. `db_query "DELETE FROM t"` → 工具结果以 `ERROR:` 开头，连库都不试；`db_query "SELECT 1"` 在项目 db.json 与密码变量配好时返回 `profile：<名字>` 加一行结果；`WHERE name = 'a;b'` 这种带分号的字符串不算多语句；没有 db.json 时报错里带路径与样板。
15. `/db` 打印配置路径、当前 profile 与可选项；`/db test` 追加 `db_change`，下一次查询走 test；`/db nope` 报错并列出可选；重启 yi 仍是 test。

LSP 另有独立用例：Go/PHP 各一条跳定义、嵌套目录里的找引用、中文路径下的定位与代码片段、带类型错误的诊断、服务器不回话时 15 秒超时、未知动作不启动服务器、配置文件里的 `gopls`/`phpantom` 被忽略。缺少服务器时用例打印 `SKIP` 并返回，不算失败。

界面层不写自动化测试，每个里程碑用一份手工检查单验收（能输入、能流式、能中断、页脚数字正确）。

## 范围外

- 记忆与自学习、任何形式的跨会话知识沉淀。
- 多供应商、多模型、模型角色划分。
- 子 agent、并行任务、MCP、扩展与钩子系统。
- `web_search`——属于第二期；`todo` 暂不做。
- TypeScript 的 LSP：机器上没有独立服务器，按“不安装新 LSP”的决定不做。
- 会话列表、分支、fork、会话树、跨项目恢复。
- 从剪贴板直接粘贴图片数据（Ctrl+V）：现在只支持「整行是图片路径」或 `@路径` 提及，拖拽到终端产生的也是路径文本。
- 产品化相关：安装器、配置向导、遥测、自动更新、Windows 支持、多用户。
- 审批与沙箱机制：工具以我的用户权限直接执行。
